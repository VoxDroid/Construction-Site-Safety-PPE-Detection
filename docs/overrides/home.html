A-101

The control room

dashboard · live view
1 2 3 4 5
  1. Title block of the day. Open violations get an ACTION stamp; compliance is measured in worker-time, not head-counts.
  2. Every worker gets a tag: ✓ for an item worn, ✗ for one missing, ? when it can't be seen. Unseen never counts as worn.
  3. A red frame means someone is in violation right now, and a clip of it is already recording.
  4. The site logbook. Each violation opens and clears with a time, linked to its evidence.
  5. Sheet index. Live, violations, analytics, reports, analyze, settings: one drawing set.
A-201

How it sees a site

one frame, real model output

General notes

  1. Detect. YOLO26 finds people, hard hats, vests, masks and bare heads in one pass.
  2. Track. ByteTrack follows each person, so a verdict belongs to a worker, not a frame.
  3. Match. Each item is assigned to the person wearing it and checked against body position. A helmet held at the waist doesn't count.
  4. Zone. Rules apply per area, measured at the feet; no-entry zones flag anyone inside.
  5. Confirm. Only an item missing for most of the delay opens a violation. One bad frame never raises an alarm.
  6. Record. Snapshot, clip, alert and a logbook entry that someone signs off.

Specification

01 · PIP
# install and start the dashboard
$ pip install "git+https://github.com/VoxDroid/ppe-guard.git"
$ ppe-guard serve
PPE Guard dashboard: http://localhost:8000
02 · DOCKER
# CPU by default; NVIDIA GPU with one build flag
$ git clone https://github.com/VoxDroid/ppe-guard.git
$ cd ppe-guard && docker compose up -d --build
03 · COMMAND LINE
# or check files without the dashboard
$ ppe-guard predict site.jpg
site.jpg: 7 worker(s), 4 non-compliant
$ ppe-guard predict shift.mp4 --save checked/
